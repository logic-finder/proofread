NAME
       proofread - removes spaces at EOL and adds a newline at EOF

SYNOPSIS
       proofread [-l] [-f] [--dry-run[=(full|line)]] [-]
       proofread [-l] [-f] [--dry-run[=(full|line)]] [--mute] + [--] <file>...
       proofread [-l] [-f] [--keep[=<path>]] [--mute] + [--] <file>...
       proofread (-h | --help)
       proofread (-v | -vv | -vvv)

       The  options  starting  with  '-' can be stated in a row, i.e. -lf. However, other options must be provided as
       stated above. Thus, it is wrong to write "--dry-run line" if it meant "--dry-run=line".

       It is impossible to mix one form with another. For instance, with the combination of the -l  and  -h  options,
       the program would print an error message.

DESCRIPTION
       proofread  corrects  two kinds of formatting problems: spaces at the end of a line (EOL) and a missing newline
       at the end of a file (EOF). These EOL and EOF problems can be addressed with the -l and  -f  options,  respec‐
       tively.

       Precisely speaking, a "space" can be either a space(' ') or a tab('\t'). Also, by a "newline", it means a line
       feed('\n'). If a carriage return('\r') is seen, the program behaves as if the character does not exist.

       In that -l and -f are both optional, this program does not inspect its input against  the  condition  not  re‐
       quested. What this implies is that if neither were specified, then it would print its output untouched.

       If the program is fed an empty file, it does nothing.

USAGE
       The behavior of this program falls into two categories: a dry-run and an actual run.

       When this program gets an execution with the --dry-run option specified, the program prints what it would have
       fixed in an actual run to the standard output. Otherwise, it performs an actual run and fix the  problems  re‐
       quested for it to handle.

       In the presence of the - option, it takes its input from the standard input and prints the result to the stan‐
       dard output. On the other hand, if the + option is specified, then the program gets the input from the file(s)
       which  are  specified after this option and it writes each result to each file. If the --keep option is speci‐
       fied with +, then the input files are kept under a given directory, which  defaults  to  "<install-path>/bak/"
       unless  provided.  Otherwise,  the original files are overwritten with the corresponding output. The filenames
       are separated with a space. Incidentally, it is encouraged to place the -- marker between "+" and filenames so
       as  to  distinguish options from filenames. Meanwhile, the program defaults to "-" if neither option is speci‐
       fied.

       Please note that if --keep were specified and the filename had a directory portion, that  part  would  be  re‐
       moved. For example, the following invocation

              $ proofread --keep=mybackup + -- dir/a.txt

       would result in "mybackup/a.txt" if everything went well.

       If  the directory name provided to --keep does not exist, the programs exits with failure. In such a case, the
       input files remain intact since the program does not directly edit the input file. Instead, the program writes
       to  a  temporary file, moves the original file under the specified directory, and gives the temp file the name
       of the input file. The name of temporary files is made by appending the string ".prfrd.tmp" to the input  file
       name (including the extension, if any).

       Incidentally, if you are going to make an actual run, especially with the + option, i.e. "overwriting option",
       it is highly recommended to make a dry-run before doing so in order to see what are to be affected.

       If multiple files are provided, each file gets an inspection with the options given in the order filenames are
       specified.

       An example dry-run session is shown below:

              $ proofread -lf --dry-run - < helloworld.c
              > proofread -l -f --dry-run=full -
              =================================================
                 1|#include <stdio.h>
                 2|
                 3|int main(void) {
                 4|   puts("Hello, World!");
                 5|   return 0;  3
                 6|}
                 7|\n

       Here,  the  program  reads  the input from stdin due to the - option. Also, by the -l option, it tests whether
       there are no redundant spaces at EOL and by -f, it checks if the last line ends with a newline. It is observed
       that  line  5  and  6 are problematic in the light of the former having three spaces at EOL and the latter not
       having a newline at EOF. In order to show the result of this inspection, the program highlights the three spa‐
       ces  with  a  red background and writes the number of spaces at the end of the line, and it writes "\n" at the
       end of the file and highlights it with a green background.

OPTIONS
       -l     Removes unnecessary spaces (if any) before the end of a line.

       -f     Puts a newline before the end of a file if there isn't.

       --dry-run, --dry-run=(full|line)
              Makes a dry-run. Defaults to "full" if specified without a value. full causes  the  whole  file  to  be
              printed, whereas line prints only lines with a problem.

       -      Uses stdin as a input.

       +      Uses the content of file(s) as a input.

       --     Denotes the end of options.

       <file>...
              Represents filename(s). Note that this does not include directory names.

       --keep, --keep=<path>
              Keeps the original file under the specified directory. Defaults to "bak/" if the value is not provided.

       --mute Suppresses the rename/remove notification when such actions happen.

       -h, --help
              Prints the manual you are reading know.

       -v     Given once, prints the version of this program. Given twice, prints the version, the installation path,
              and the information related to this program. Meanwhile, a question mark hangs over  this  option  being
              given  three  times.  Let's  leave  it as the delight of when executed for real. Suffice it to say that
              you'll like it.

EXAMPLES
       * Checking for EOL and EOF Problems

              $ proofread -lf --dry-run=line - < input.txt

       With input.txt redirected, the program checks whether there are EOL and EOF problems and prints the result  of
       the inspection to the standard output.

       * Checking for Multiple Files

              $ proofread -lf --dry-run=line + -- a.txt b.txt c.txt

       The  program reads the three files and checks for each file whether it has EOL and EOF problems. The result is
       printed to stdout file by file.

       * Fixing EOL and EOF Problems

              $ proofread -lf + -- input.txt

       The program reads one file, which is input.txt, and fixes EOL and EOF problems in that file. Notice that  this
       operation modifies the file.

       * Keeping the Original File under a Specific Directory

              $ proofread -lf --keep=backup/ + -- input.txt

       The  program  reads  input.txt and fixes EOL and EOF problems in that file. After the correction, it saves the
       original file under the "backup/" directory.

       * Setting Up a Pre-commit Hook

       There is a pre-commit hook which is executed automatically when one executes git commit.  This  hook  executes
       proofread  on  the files which are staged (by a prior git add) and whose state is modified or newly added. Its
       behavior differs depending on whether the file has local changes or not. If it has, the hook updates the index
       only. Otherwise, the hook updates both the index and the worktree.

       In  order  to use it, one must compile it first and place the executable under the .git/hooks directory of the
       desired git repository:

              $ make hook EXT_LIST='".c", ".h"' SHUTUP=1
              $ cp hook/pre-commit <git-repo>/.git/hooks

       When making the pre-commit hook, one can control two variables:

              EXT_LIST
                     Defines the extensions to apply proofread. The value must be enclosed with a  single-quote  mark
                     and  each  extension  must  be enclosed with a double-quote mark. The extensions are comma-sepa‐
                     rated. If not specified, all of the files which meet the above conditions are subject to the ap‐
                     plication.

              SHUTUP Sets the verbosity of the hook. The value of 1 means true and 0, false.

       If  the  hook  is  executed with l option, it prints out the extension list at stdout, exiting with the status
       code 2.

EXIT STATUS
       The program exits with EXIT_SUCCESS on normal status. Otherwise, EXIT_FAILURE.

FILES
       <file>.prfrd.tmp
              As mentioned above, it is a temporary file created during the fix.
       .prfrd.short-status
       .prfrd.checkout-index-temp
       .prfrd.hash-object-temp
       .merge_file_*
              Temporary files used by the pre-commit hook. Deleted automatically.
       dat/proofread.1
              The manual page file. Used when the --help option is specified.
       dat/proofread.1.txt
              The text version of the manual page. The program falls back to this file when man(1) is not available.
       dat/version.txt
              A text file containing the version of this program.
